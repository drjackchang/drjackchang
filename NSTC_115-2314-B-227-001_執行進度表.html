04 Delphi 共識問卷——主要題項（M4）

以下為向 20–25 名臨床與公衛專家施測的 Delphi 問卷題項草稿。每題以四個構面評分（1–7 Likert）：重要性、可行性、可比性（跨院）、政策應用價值。題項設計以「年報應呈現什麼」為核心，對標 VSTR 五大區塊。

一、基本人口輪廓指標（Trauma Profile）｜對應 VSTR「Demographic profile」
  • Q1
    每年住院重大創傷人數（含年齡別標準化發生率，per 100,000 人口）
  • Q2
    年齡分布（依六個年齡層報告：<5、5–17、18–44、45–64、65–74、≥75）
  • Q3
    性別分布（生理性別；男 / 女 / 其他）
  • Q4
    受傷機制分類（交通事故、跌倒、暴力傷害、運動傷害、其他，分別報告）
  • Q5
    跌倒細分（低處跌倒 ≤1 公尺 vs 高處跌倒 >1 公尺）應獨立呈現
    VSTR 近五年數據顯示低處跌倒超越交通事故，成為台灣最主要的機制，高齡化趨勢下此指標將快速升溫
  • Q6
    受傷地點分類（住家、道路、工作場所、休閒場所、其他）
  • Q7
    受傷時間分布（4小時時段、星期幾）
  • Q8
    事故發生地之城鄉分類（都市 / 非都市 / 偏遠），含各類別發生率
二、傷害嚴重度與類型（Injury Severity & Type）｜對應 VSTR「Injuries sustained」
  • Q9
    創傷嚴重度評分（ISS）分布，以 ISS ≥16 作為「重大創傷」報告門檻
  • Q10
    頭部傷害嚴重度應獨立呈現（AIS head score + 到院 GCS，按機制分類）
  • Q11
    主要傷害解剖位置分類（頭頸部、胸腹部、四肢、多重創傷）
  • Q12
    脊髓損傷案例應在年報中獨立呈現
  • Q13
    燒傷案例（TBSA ≥20%）應在年報中獨立呈現
  • Q14
    傷害意圖應列入年報（非蓄意 / 蓄意自傷 / 他傷或暴力）
    此欄位影響政策方向：自傷案例需心理衛生資源，暴力傷害需治安政策，不宜合併呈現
三、就醫流程指標（Patient Flow & Triage）｜對應 VSTR「First hospital and definitive care」
  • Q15
    第一接收醫院層級分布（急救責任醫院各等級）
  • Q16
    最終照護醫院層級（定性照護是否達適當等級，按台灣分級報告）
  • Q17
    由事故現場直接轉送至創傷中心的比率（direct admission rate）
  • Q18
    跨院轉診比率（inter-hospital transfer rate）
  • Q19
    轉診目的地合規率（是否符合創傷分流指引，destination compliance rate）
    VSTR 2022-23 為 94.7%；台灣目前尚無統一指引，此指標可作為指引建立後的基線
  • Q20
    直升機（HEMS）救護使用率應在年報中呈現
四、院前救護與系統時間指標（Pre-hospital & System Time Indicators）｜對應 VSTR「Trauma system indicators」
  • Q21
    緊急救護到達現場時間（response time，中位數 + 第90百分位）
  • Q22
    現場處置時間（scene time，從到場至離開）
  • Q23
    到達最終照護醫院的總時間（含跨院轉診時間）
  • Q24
    跨院轉診等待時間（inter-hospital transfer time，中位數）
  • Q25
    外傷小組啟動率（trauma team activation rate）
五、住院結局指標（In-hospital Outcomes）｜對應 VSTR「Hospital outcomes」
  • Q26
    院內死亡率（全體 + 依傷害機制分類）
  • Q27
    院內死亡時序分析（<24小時 / 1–7天 / >7天）
  • Q28
    年齡別死亡率（65歲以上應獨立呈現）
  • Q29
    住院天數（中位數，按傷害機制分類）
  • Q30
    加護病房（ICU）入住率與住 ICU 天數（中位數）
  • Q31
    機械通氣使用率（含使用時數中位數）
  • Q32
    出院狀態分布（返家 / 轉復健 / 轉長照機構 / 自動出院 / 死亡）
六、死亡率指標（Mortality Indicators）｜對應 VSTR「All trauma deaths」
  • Q33
    院內創傷死亡人數與粗死亡率（需按年齡標準化）
  • Q34
    各傷害機制別死亡率應分別呈現（交通、跌倒、暴力等）
  • Q35
    65歲以上老年族群死亡率應獨立呈現並進行五年趨勢分析
  • Q36
    年報中應納入到院前死亡估算值（需與衛福部死因統計連結）
    VSTR 透過 NCIS（法醫資料庫）取得，台灣可行性視衛福部資料連結協商進度，R1 讓專家先評估意願
七、資料治理可行性（本土化維度）
  • Q37
    各院現行登錄系統是否具備支撐上述指標所需欄位
  • Q38
    年報資料應達到的最低時效性要求（季報 / 半年報 / 年報）
  • Q39
    跨院欄位口徑統一的可行性（是否有意願配合標準化）
  • Q40
    受傷地點地理資訊（行政區或座標）目前在各院的可及性
開放式題項（每輪各一題）
  • 開1
    您認為台灣創傷登錄年報中，最迫切需要建立但目前最難執行的指標是什麼？請說明理由。

05 Data Lake 架構定位

本計畫的 Data Lake 分四個層次。本計畫預算與範疇對應 Level 1（做扎實）+ Level 2（做示範）+ Level 3（寫藍圖）。Level 4 屬部會級計畫，不在現階段範疇。

本計畫執行
Level 1
研究用概念驗證
結構化資料治理框架，跑在免費雲端或本機工作站。產出「架構文件 + 可重現 ETL 腳本 + 示範資料集」。
技術：Python · DuckDB / Pandas · Google Cloud Storage · 資料字典 v1.0（metadata schema）
本計畫示範
Level 2
機構級輕量部署
需北護或高醫 IT 配合。不需額外預算，但需行政協調開放伺服器資源。Phase 1 結束後部署。
技術：PostgreSQL · PostGIS · Apache Airflow / cron · Metabase（BI）
下一期計畫
Level 3
跨院資料交換層
FHIR 標準介面 + API Gateway，需各院 IT 正式介接，需衛福部資料治理授權。預算規模 >1,000 萬。
本計畫交付物（指標集 + 欄位標準 + ETL 規格書）= Level 3 的前置規格文件
部會級計畫
Level 4
國家級創傷資料平台
